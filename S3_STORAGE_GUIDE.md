# S3: файлы и видео BTBS

С 30.10.2026 LMS подключена к AWS S3: приватный bucket `btbs-lms-media-506546664509-eu-north-1`, регион `eu-north-1` (Стокгольм). Пять существующих файлов перенесены, локальные оригиналы сохранены. Файлы хранятся отдельно от приложения; в базе остаются названия, права и ключи объектов. Поддерживаются AWS S3 и совместимые сервисы с presigned POST, CopyObject, Range GET и подписанными ссылками.

## Действующая конфигурация

- Block Public Access включён, ACL отключены, шифрование SSE-S3. Анонимное скачивание объектов запрещено.
- IAM user `btbs-lms-storage` без входа в AWS Console, один ключ только в `backend/.env`. Объектные права ограничены `_s3/` и `_staging/`; полный JSON — `deployment/s3/btbs-lms-storage-policy.json`. Скачанный CSV с ключом удалён после импорта.
- CORS разрешён для `http://127.0.0.1:5173`, `http://localhost:5173` и `https://father-edwards-praise-strengthening.trycloudflare.com`. При смене внешней ссылки обновите CORS через AWS Console: сервисному пользователю управление bucket не разрешено.
- Lifecycle `CleanOnlyTemporaryLmsUploads` удаляет `_staging/` и незавершённые multipart uploads через сутки. Опубликованные `_s3/` объекты не затрагиваются.
- Резервная копия базы и прежних настроек: `.local/backups/before-live-s3-20261030/`. Содержимое всех пяти перенесённых файлов сверено по SHA256; подписанные ссылки и Range-запросы проверены на настоящем S3.

## Подключение

1. Создайте отдельный приватный bucket у выбранного провайдера. Для AWS оставьте включённым Block Public Access и отключённые ACL. Выберите регион и шифрование на стороне хранилища. Приложению не нужен публичный доступ к bucket.
2. Создайте серверный IAM principal с доступом только к этому bucket. Для проверки соединения/существования объектов нужен `s3:ListBucket` на bucket; для загрузки, чтения, копирования и удаления — `s3:PutObject`, `s3:GetObject`, `s3:DeleteObject` на его объектах. CopyObject использует GetObject источника и PutObject назначения. При собственном KMS-ключе отдельно настройте необходимые KMS permissions. Не выдавайте `s3:*` на все bucket.
3. В PowerShell из папки LMS установите зависимости:

   ```powershell
   .\backend\.venv\Scripts\python.exe -m pip install -r .\backend\requirements.txt
   ```

4. В локальном `backend/.env` задайте значения из кабинета провайдера:

   ```dotenv
   MEDIA_STORAGE_MODE=s3
   MEDIA_S3_BUCKET=your-private-bucket
   MEDIA_S3_REGION=your-region
   MEDIA_S3_ENDPOINT=
   MEDIA_S3_ACCESS_KEY=your-access-key
   MEDIA_S3_SECRET_KEY=your-secret-key
   MEDIA_S3_ADDRESSING_STYLE=auto
   ```

   Для AWS `ENDPOINT` оставьте пустым: приложение формирует региональный endpoint, чтобы перенаправление между регионами не ломало подпись ссылки. Для совместимого сервиса укажите его HTTPS endpoint и рекомендованный `ADDRESSING_STYLE` (`auto`, `virtual` или `path`). При использовании AWS IAM role ключи можно оставить пустыми: boto3 использует стандартную credential chain. Ключи не помещаются в frontend, описание курса или Git. Перезапустите backend и сервер внешней ссылки после изменения `.env`.

5. Разрешите CORS в bucket для **точных адресов вашего приложения**. Пример для локального приложения; для внешней ссылки добавьте её origin без завершающего `/`:

   ```json
   [{
     "AllowedOrigins": ["http://127.0.0.1:5173", "http://localhost:5173"],
     "AllowedMethods": ["POST", "GET", "HEAD"],
     "AllowedHeaders": ["*"],
     "ExposeHeaders": ["ETag", "Content-Length", "Content-Range", "Accept-Ranges"],
     "MaxAgeSeconds": 600
   }]
   ```

   При смене временной ссылки Cloudflare обновляйте origin в CORS. CORS не делает bucket публичным и не заменяет IAM.

6. Войдите системным администратором или владельцем → **Система и хранилище** → **Проверить подключение S3**. Проверка делает HEAD bucket. После неё загрузите короткое тестовое видео через преподавательский кабинет и проверьте просмотр учеником. HEAD bucket сам по себе не проверяет CORS, все объектные права и воспроизведение.

## Загрузка и доступ

С 04.11.2026 файлы автоматически группируются по курсам: `_s3/courses/course-ID/`. Внутри — изображения курса, материалы/видео/иллюстрации по урокам и ответы по группам/заданиям/попыткам. Структура и правила переноса: [S3_ARCHITECTURE.md](S3_ARCHITECTURE.md). Системный администратор видит соответствие названий и папок в блоке «Файлы по курсам». Папка появляется после первой загрузки; переименование курса не требует переноса файлов.

- Через «Загрузить файл / видео» видео до **2048 МБ** отправляется напрямую из браузера в S3; документы — до **20 МБ**. Есть индикатор прогресса и отмена передачи. Это одна presigned POST-загрузка, без возобновления с места обрыва. При обрыве нужно выбрать файл заново.
- Сначала создаётся временный объект `_staging/`. Сервер сверяет размер, MIME и сигнатуру формата, затем копирует конкретную версию по ETag в новый неизменяемый ключ `_s3/`. Повторный вызов завершения не создаёт копию материала. Подпись формата проверяет тип файла, но не заменяет антивирусную проверку.
- После проверки создаются материал и шаг урока. Публикация наследует состояние урока. Доступ ученика зависит от записи в группу, публикации и даты открытия модуля.
- При просмотре LMS сначала проверяет права, потом выдаёт подписанный URL: видео на **1 час**, остальные файлы на **10 минут**. Это bearer URL: тот, кто получил ссылку, может пользоваться ей до истечения срока. Отзыв записи блокирует новые ссылки; уже выданная действует до истечения подписи. Это не DRM. После истечения ссылки повторно откройте материал из LMS.
- Изображения описаний курсов, иллюстрации уроков и ответы-файлы также сохраняются в выбранном backend. Картинки описания опубликованного курса доступны аудитории этого описания; приватные материалы остаются за проверкой LMS.
- Старые локальные файлы продолжают открываться и после включения S3. При возврате `MEDIA_STORAGE_MODE=local` новые файлы сохраняются локально, а уже сохранённым S3-объектам по-прежнему нужны параметры доступа к bucket.

## Перенос существующих файлов

Сделайте резервную копию базы и папки `backend/media`. Сначала посмотрите количество файлов (ничего не меняет):

```powershell
cd backend
.\.venv\Scripts\python.exe manage.py migrate_media_to_s3
```

После настройки и проверки S3:

```powershell
.\.venv\Scripts\python.exe manage.py migrate_media_to_s3 --execute
```

Команда копирует уникальные файлы материалов, изображений описания и ответов учеников, сверяет размеры и обновляет ссылки в базе. Локальные оригиналы сохраняются для восстановления. Уже перенесённые объекты пропускаются. Перенос пообъектный: при сбое исправьте подключение и повторите команду. Для отката ссылок используйте резервную копию базы.

## Обслуживание

```powershell
cd backend
.\.venv\Scripts\python.exe manage.py cleanup_media_uploads
```

Команда удаляет просроченные временные объекты и повторяет неудавшиеся удаления файлов без ссылок в базе. Запускайте её регулярно через планировщик сервера; автоматическое расписание вне приложения ещё не устанавливалось. Lifecycle для `_staging/` через сутки уже включён в AWS, но он не очищает записи сессий и очередь повторных удалений в базе. Не распространяйте это правило на `_s3/`.

Стоимость bucket, запросов и исходящего трафика зависит от провайдера. Адаптивное HLS-видео, транскодирование и CDN — отдельный следующий этап; текущая реализация хранит и воспроизводит исходные MP4/WebM.

Документация: [django-storages S3](https://django-storages.readthedocs.io/en/stable/backends/amazon-S3.html), [S3 presigned URLs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html), [S3 GET/Range](https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetObject.html).
