# Изменения AWS для утверждения — 13 ноября 2026

Аккаунт 506546664509, регион eu-north-1. Шаблон cloudfront-private.json прошёл AWS validate-template; нужны IAM capabilities.

1. Создать стек btbs-private-media: приватный CloudFront с OAC, доверенной группой открытого ключа и HTTPS. Закрытый ключ остаётся на компьютере. Чтение только _s3/* существующего btbs-lms-media-506546664509-eu-north-1, только этим distribution. Правило добавляется к существующей bucket policy без удаления других правил.
2. Дополнить CORS существующего bucket: PUT для multipart, localhost/127.0.0.1:8080. Сохранить прежние разрешённые origins и методы. Незавершённые загрузки очищаются через сутки по существующему lifecycle.
3. Дополнить права btbs-lms-storage: AbortMultipartUpload и ListMultipartUploadParts только _staging/*; прочие текущие политики не менять.
4. Создать отдельный приватный bucket btbs-lms-backups-506546664509-eu-north-1 с versioning, AES256, блокировкой публичного доступа и запретом HTTP. Архивы encrypted/* хранятся 30 дней; предыдущие версии удаляются через 7 дней после перехода в предыдущую версию. При удалении стека bucket сохраняется (Retain).
5. Разрешить существующему сервисному пользователю читать и записывать только encrypted/* в backup bucket, включая чтение конкретной версии и очистку незавершённой multipart-передачи. Не выдавать DeleteObject/DeleteObjectVersion и административный доступ. Новые ключи доступа не создаются. Это один аккаунт и тот же сервисный пользователь: от компрометации владельца AWS такой вариант не защищает.
6. Включить конфигурацию локально после проверок; отправить зашифрованный архив существующих данных LMS в новый bucket. Ключ резервных копий не загружать. Скачать архив обратно и проверить восстановление в отдельной базе, не подменяя рабочую.

CloudFront, S3, запросы и трафик оплачиваются по тарифам AWS; это не фиксированный бесплатный тариф. Новые платные подписки и домены не оформляются. Публичного доступа к архивам/курсам не будет.
