# Подтверждённые и применённые настройки S3 — 30.10.2026

Bucket: `btbs-lms-media-506546664509-eu-north-1`, регион `eu-north-1` (Стокгольм).
Создан с Block Public Access, отключёнными ACL и SSE-S3. Публикация bucket не требуется.

Владелец подтвердил весь план ответом «Да, применяй все эти настройки». Выполнено:

1. Сервисный IAM user `btbs-lms-storage`, без входа в AWS Console. Политика `BTBSLmsStorage`: ListBucket/GetBucketLocation только для этого bucket; GetObject/PutObject/DeleteObject только внутри `_staging/` и `_s3/`. Полный JSON: `btbs-lms-storage-policy.json`.
2. Один программный access key этого IAM user для backend LMS. Сохранение только в локальном `backend/.env`; root access key не создаётся. Ключи не попадают в frontend, документацию и чат.
3. CORS только для двух локальных адресов LMS и текущей внешней ссылки из `cors.json`. Эти правила не предоставляют анонимный доступ к объектам. При смене временного origin Cloudflare его нужно обновить.
4. Lifecycle из `staging-lifecycle.json`: удаление только временных `_staging/` объектов через сутки и незавершённых multipart uploads. Опубликованные `_s3/` файлы этим правилом не затрагиваются.
5. Проверка небольшим тестовым файлом, затем перенос пяти текущих вложений LMS (материалы уроков, изображения описаний курсов, файлы ответов учеников) в приватный bucket. Локальные оригиналы сохраняются. Резервная копия настроек: `.local/backups/before-live-s3-20261030/backend.env`; перед переносом также сохраняется актуальная база.

Backend работает в режиме S3. Созданы пользователь без входа в Console и один ключ, сохранённый только в `backend/.env`. CSV удалён после импорта. Применены CORS и lifecycle; сохранённая IAM policy сверена с согласованным JSON. Перенесены все пять файлов, SHA256 каждого совпадает с локальным оригиналом. Оригиналы сохранены; резервная копия базы — `.local/backups/before-live-s3-20261030/database.json`.

Реальными запросами проверены запись, чтение, подписанные ссылки, Range, разрешённые CORS origins, отказ для постороннего origin, запрет анонимного доступа и управления bucket сервисным пользователем. Исправлено формирование регионального endpoint для подписанных ссылок AWS.
