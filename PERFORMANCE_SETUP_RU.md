## Что работает сейчас

* Завершённость шагов считается одним SQL-запросом с EXISTS вместо отдельного обращения для каждого шага. Права редактора и преподавателя в каталоге также выбираются вместе с курсами.
* На странице структуры курса проверка прав выполняется один раз для списка; даты модулей загружаются одним запросом. Проверки публикации, начала группы и обязательных предыдущих шагов сохранены.
* «Моё обучение» пакетно пересчитывает прогресс и сохраняет историю под блокировками записей зачисления. Данные разных студентов и групп не смешиваются. Назначения и сроки предзагружаются.
* PostgreSQL-соединение можно повторно использовать до 60 секунд, с проверкой здоровья соединения. `DB_CONN_MAX_AGE=0` отключает повторное использование. Число соединений зависит от числа серверных потоков/процессов — не повышать их бесконтрольно.
* В кэше хранятся только два счётчика уроков на курс. Срок жизни 30 секунд; обычное сохранение/удаление урока очищает ключ сразу и после commit. Массовые изменения через bulk/update обходят сигналы, поэтому счётчик может отставать до 30 секунд. Права, оценки, ответы и доступ к материалам всегда проверяются по базе.
* При недоступности кэша счётчики вычисляются из базы. По умолчанию используется ограниченный кэш в памяти каждого процесса, без файлов на диске.

## Redis: подключение подготовлено, сервер пока не запущен

Установлен Python-клиент из `backend/requirements-cache.txt`. На этом Windows-компьютере нет Docker и установленной подсистемы WSL. Redis-сервис не установлен; результаты локальных тестов получены без Redis.

На будущем сервере установить Redis в закрытой сети/на loopback. Добавить в локальные серверные настройки `LMS_REDIS_URL=redis://127.0.0.1:6379/1` (пример без пароля для изолированного локального сервиса) и перезапустить процессы LMS. Для удалённого сервиса нужны аутентификация и защищённое соединение. Не публиковать порт 6379 в Интернет. Секретный URL не сохранять в Git и не отправлять в чат.

Это выделенный удаляемый кэш: ограничить память, например 128 МБ, разрешить вытеснение старых ключей. Не использовать тот же экземпляр с вытеснением для будущей очереди Celery. Сессии и основная информация по-прежнему в PostgreSQL. Celery не добавлен.

## Файлы и видео

В проекте уже существует прямая загрузка браузер → S3: `/api/media/config/` сообщает режим, сервер проверяет редактора и выдаёт временную подписанную форму. Перед публикацией проверяются размер, тип и сигнатура файла, объект копируется из staging в отдельный ключ курса. Большой файл через Django не передаётся. Текущий лимит видео при S3 — 2048 МБ, документов — 20 МБ. Скачивание защищено проверкой доступа и временными ссылками.

Это одиночная загрузка, а не multipart: при обрыве большой файл нужно отправлять заново. Возобновляемая загрузка, CDN и перекодирование видео пока не добавлены. Для CDN и Nginx понадобятся адрес будущего сервера, домен и настройка приватной выдачи. Нынешнюю работающую приватность S3 не меняли.

## Проверки и повторение

Запускать из `backend`: `.venv\Scripts\python.exe manage.py test learning courses analytics assessment --noinput`. Теперь обычный `manage.py test` выбирает отдельные локальные тестовые настройки: настоящая S3-конфигурация не должна получать тестовые файлы. Проверки подписей S3 используют тестовые реквизиты, остальные операции S3 имитируются.

Нагрузка: `.venv\Scripts\python.exe load_probe_local.py`. Создаётся отдельная PostgreSQL-база, локальный HTTP-сервер на 18765, затем база удаляется. Отчёт — `LOAD_TEST_AFTER.json`; исходный результат сохранён в `LOAD_TEST_RESULTS.json`. Не запускать одновременно с другими тестами, чтобы они не искажали замер. Это короткий GET-тест синтетических курсов, а не проверка тысячи пользователей, видео или массовой авторизации.
