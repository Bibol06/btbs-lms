# BTBS LMS: что сделано и как понимать проект

Состояние на 5 ноября 2026 года. Документ составлен по коду, README, инструкциям и журналам проверок. Это действующий локальный проект с временным внешним доступом. Постоянное размещение пока не выполнено.

## 1. Рассказ работодателю за одну минуту

«В BTBS реализован полный основной учебный цикл: преподаватель создаёт курс, модули, уроки и задания; студент записывается, изучает материалы и сдаёт работы; преподаватель видит ответы, проверяет их и выставляет оценки. Есть самостоятельное обучение и группы с отдельными сроками и результатами.

Созданы разные кабинеты студента, преподавателя, администратора обучения и системного администратора. Добавлены обсуждения с ответами в ветках, объявления, личные сообщения, уведомления и аналитика. Интерфейс работает на русском, казахском и английском.

Файлы подключены к приватному AWS S3 и организованы по курсам. Настроены зашифрованные резервные копии с проверенным восстановлением, а также восстановление пароля через Gmail. Проверяются права доступа, учебные сценарии, загрузка файлов, сроки, переводы и восстановление. Внешний доступ и вход с телефона проверены. Следующий большой этап — постоянное размещение и подготовка к эксплуатации».

## 2. Что делает LMS

LMS — Learning Management System, система управления обучением. Это не только каталог видео. Она связывает материалы, людей, доступ, задания, оценки, общение и результаты.

Основная цепочка:

```text
создать курс → подготовить программу → опубликовать
→ записать студентов → открыть нужные материалы
→ получить ответы → проверить → показать результат
```

Ключевые сущности нашей базы:

| Сущность | Значение |
|---|---|
| User | Учётная запись человека |
| Course | Содержание курса и его общие настройки |
| CourseRun | Конкретная группа или самостоятельный запуск курса |
| Enrollment | Запись определённого студента на конкретный запуск |
| Module | Крупный раздел программы |
| Lesson | Урок внутри программы |
| Step | Отдельный учебный шаг: текст, материал, тест, задание или Python |
| Submission | Конкретная отправка работы студентом |
| QuizAttempt | Конкретная попытка теста |
| StepProgress | Прогресс определённого прохождения по шагу |

Почему отдельно Course и CourseRun: содержание Python может быть одним, а группы А и Б начинают в разные дни. У них свои ученики, дедлайны и результаты. Если записать сроки прямо в общий курс, изменение для группы А случайно затронет группу Б.

Почему нужен Enrollment: результат принадлежит не просто человеку, а его конкретному прохождению. Одному студенту можно заново пройти курс в другой группе без смешивания двух историй.

## 3. Реализованные возможности

### Учётные записи и кабинеты

Есть регистрация, вход, выход и профили. Имя человека отделено от его логина и роли. Саморегистрация создаёт студента; передача role=admin в запросе не даёт административных прав.

После последнего исправления можно входить по логину или зарегистрированному email. Регистр букв и случайные пробелы по краям идентификатора не мешают входу. Сам пароль не обрезается и не изменяется программой. Если идентификатор неоднозначен между двумя аккаунтами, вход отклоняется.

Кабинеты различаются по задачам, а сервер проверяет полномочия независимо от того, какие кнопки видны на странице.

| Роль | Область ответственности |
|---|---|
| Студент | Свои курсы, ответы, результаты, сроки и общение |
| Преподаватель | Назначенные курсы и группы, создание материалов, проверка, результаты |
| Администратор обучения | Учебный процесс по платформе: курсы, группы, преподаватели, результаты и проверки |
| Системный администратор | Пользователи, состояние приложения, БД и хранилища, история входов и устройств |
| Владелец | Полный доступ и назначение административных областей |

Это две административные роли, а не ограничение ровно двумя сотрудниками. Системная роль в интерфейсе не выдаёт автоматически доступ к Windows, AWS Console или секретным ключам.

### Создание и прохождение курса

Есть курсы, модули, уроки, учебные шаги, черновики и публикация. Интерфейс преподавателя и навигация студента упрощались с учётом сценариев Stepik, при этом сохранён собственный стиль BTBS.

Можно добавлять текст, изображения в описание курса и учебные материалы, документы и видео. Реализованы встроенные учебные тесты, предпросмотр, банк вопросов с версиями и копирование содержания курса в новый черновик без студентов и их оценок.

У студента есть программа курса, переходы между шагами, продолжение обучения и прогресс. Прохождение учитывает обязательные шаги и результаты, а не только факт открытия страницы.

### Работы, тесты и Python

Письменное задание принимает текст и/или допустимый файл. Сохраняются отправки, попытки, проверки, оценки и комментарии. Есть возврат на доработку, история проверок и журнал результатов.

Преподаватель может посмотреть, что конкретно написал ученик и какие варианты выбрал в тесте. У тестов есть лимиты попыток, время, сохранение ответов и автоматическая проверка. Условия проверяются сервером: изменение часов телефона не продлевает серверный срок.

В Python-задачах есть редактор, пробный запуск со своим вводом и проверка на тестах. Wasmtime/WASI используется для изолированного исполнения. Это не запуск ученического кода с обычными правами серверного Python. Изоляция и ограничения ресурсов не заменяют дальнейшую проверку безопасности перед массовой эксплуатацией.

### Сроки и контрольные работы

Преподаватель задаёт дату открытия и дедлайн модуля для выбранной группы вручную. Автоматического обязательного открытия каждого следующего модуля по номеру недели сейчас нет.

После дедлайна модуль остаётся доступным. Незавершённый модуль помечается просроченным; ожидающая преподавательской проверки работа учитывается отдельно. Дедлайн модуля не переписывает собственное окно теста или правила сдачи конкретного задания.

Недельные и четырёхнедельные контрольные тесты настраиваются отдельно. «Месячный» контроль означает четыре учебные недели от начала обучения, а не календарный месяц. Даты можно переопределять.

### Общение

Есть объявления по курсу/группе, личные диалоги и обсуждения урока. Ответы прикрепляются к исходному вопросу в ветке. Очередь вопросов помогает увидеть, где ученик ждёт преподавателя. Есть внутренние уведомления и напоминания.

Не следует говорить, что абсолютно все уведомления отправляются по email: подтверждённая реальная почтовая интеграция сейчас относится к восстановлению пароля.

### Аналитика

Студент видит свой прогресс и результаты. Преподаватель — данные доступных групп, первые попытки, частые ошибки и обратную связь о понятности материала. Администратор — общие результаты, нагрузку, действия, дни активности и доступную историю входов/устройств.

Есть периоды 7/30/90 дней и произвольный диапазон, фильтры и CSV-выгрузки. Сравнение входного и итогового теста помогает наблюдать изменение результатов.

Рост баллов не доказывает, что именно один урок вызвал улучшение. На результат влияют повторные попытки, исходная подготовка и другие занятия. Также открытая вкладка не доказывает, что человек всё время учился. Модель устройства и местоположение нельзя гарантированно установить по данным браузера. За прокси IP может принадлежать прокси.

### Языки и дизайн

Русский, казахский и английский применяются к интерфейсу, системным статусам, ошибкам, датам и отчётам. Предпочтение языка сохраняется. BTBS остаётся BTBS на всех языках.

Язык интерфейса отделён от языка учебного содержания. Английский курс, исходный код, имена и авторские сообщения нельзя слепо заменять словарём интерфейса. Подготовленные переводы содержимого поддерживаются; новые произвольные материалы не получают автоматически качественный перевод на три языка.

Использованы четыре исходных логотипа BTBS, единый стиль карточек, форм и таблиц, боковая навигация и мобильные варианты расположения элементов.

## 4. Из чего технически состоит проект

```text
Телефон / браузер
        ↓ HTTP-запросы к API
React + TypeScript: интерфейс
        ↓
Django: правила, проверки, права и обработка запросов
        ├── PostgreSQL: пользователи, курсы, ответы, оценки, сроки
        ├── AWS S3: видео, изображения, документы, вложения
        ├── SMTP Gmail: отправка писем восстановления
        └── фоновые процессы: уведомления, снимки аналитики,
            доставка писем и резервное копирование
```

Frontend — часть приложения в браузере. React помогает собирать интерфейс из компонентов; компонентом может быть форма входа или карточка курса. TypeScript проверяет согласованность типов при разработке, но не заменяет серверную проверку запросов. Vite запускает среду разработки и собирает файлы интерфейса для внешнего приложения.

Backend — серверная часть. Django получает запрос, проверяет пользователя, данные и правила, обращается к БД/хранилищу и возвращает ответ.

API — согласованный способ общения интерфейса с сервером. Например, браузер отправляет JSON с ответом на задание. JSON — формат передачи структурированных данных. HTTP — протокол запросов и ответов; HTTPS добавляет защищённое соединение.

PostgreSQL — база связанных таблиц. Foreign key, или внешний ключ, связывает записи: урок относится к конкретному курсу. ID — устойчивый идентификатор записи. Название курса можно поменять, ID при этом остаётся прежним.

ORM — слой Django для работы с таблицами через Python. Миграция — описанное изменение структуры базы: например, добавление поля дедлайна. Изменить только Python-файл модели недостаточно: миграцию нужно создать и применить.

Транзакция объединяет изменения базы в одну операцию: либо сохраняется согласованный результат, либо изменения откатываются. S3 — отдельная система, поэтому откат БД сам по себе не удаляет уже загруженный объект; нужны уборка и повторные попытки удаления.

Основные каталоги backend: accounts — аккаунты и системные функции; courses — курсы и группы; learning — программа и материалы; assessment — задания, тесты и оценки; communication — общение; analytics — отчёты; codejudge — Python-задачи. Страницы и компоненты интерфейса находятся в frontend/src.

## 5. Как подключён S3

Amazon S3 — сервис объектного хранения AWS. Bucket — контейнер объектов. Object — сам файл с метаданными. Key — адрес объекта внутри bucket.

«Папка» S3 — общий префикс ключа, а не обычная папка диска. Пример:

```text
_s3/courses/course-10/lessons/lesson-25/videos/<UUID>.mp4
_s3/courses/course-10/images/<UUID>.png
_s3/courses/course-10/groups/run-16/assignments/assignment-8/
    answers/enrollment-21/attempt-1/<UUID>.pdf
```

UUID — случайный идентификатор имени объекта. Два файла video.mp4 не перезапишут друг друга. Для пути используются ID, чтобы переименование курса не потребовало переносить файлы.

Bucket приватный, регион — Стокгольм. Backend проверяет права и выдаёт временную подписанную ссылку. Это URL с ограниченным сроком/условиями доступа; обычная ссылка на приватный объект сама по себе не делает его публичным.

При прямой загрузке материал сначала попадает в _staging, то есть временную зону. Сервер проверяет размер, тип и служебные данные загрузки, формирует итоговый путь и связывает объект с учебной записью. Незавершённые staging-объекты очищаются по правилу через сутки. Для прямого пути видео предусмотрен лимит до 2048 МБ; другие пути загрузки имеют свои ограничения.

IAM — управление правами AWS. Сервисному пользователю даны ограниченные права на области LMS, а ключи находятся в закрытых серверных настройках. CORS определяет, с каких сайтов браузер может обращаться к хранилищу; он не заменяет авторизацию LMS и IAM.

Пять существующих вложений перенесены в структуру по курсам с сохранением оригиналов. S3 хранит видео, но это не готовая видеоплатформа: адаптивное качество, перекодирование, CDN и DRM отдельно не заявлены как реализованные.

## 6. Резервные копии и восстановление

Backup — резервная копия, из которой можно восстановить данные. Наличие файла архива ещё не доказывает, что он пригоден: нужна пробная распаковка и восстановление.

У нас архив включает согласованный снимок PostgreSQL и используемые вложения, включая S3. Для снимка используется pg_dump. Архив зашифрован AES-256-GCM; ключ хранится отдельно. Без исходного ключа расшифровать старую копию нельзя.

Windows-задача запускает копирование ежедневно в 03:00 по текущему локальному времени. Есть ручная кнопка, состояние выполнения, повтор после пропуска и хранение семи последних успешных копий. Создание не заменяет предыдущую успешную копию неудачным архивом.

Выполнены реальные восстановления в отдельные тестовые базы. Сверялись количества основных записей и пять вложений по SHA-256. SHA-256 здесь — контрольный отпечаток содержимого, позволяющий обнаружить отличие файлов, а не способ шифрования.

Рабочие архивы: .local/backups/scheduled. Ключ: .local/backup-keys/main.key. Автоматическая внешняя копия архивов пока не настроена: если всё хранится на одном диске, поломка диска остаётся риском. Нужны и архив, и отдельно сохранённый ключ.

## 7. Пароли, почта и доступ с телефона

Пароли аккаунтов хранятся как хеши, а не как открытый текст. Хеш пароля позволяет проверить введённое значение, но не предназначен для восстановления исходного пароля. Забытый пароль заменяют новым через подтверждение доступа к почте.

SMTP — протокол отправки писем, его не нужно «скачивать». LMS подключена к SMTP Gmail. Используется отдельный пароль приложения Google, введённый владельцем локально. Это не пароль студента и не основной пароль Google.

Пользователь вводит зарегистрированный email → сервер создаёт запрос доставки → фоновая служба отправляет письмо этому аккаунту → пользователь открывает ограниченную по времени ссылку → задаёт новый пароль. Ссылка действует час, перестаёт работать после смены пароля, прежние сессии теряют доступ. Session, или сессия, — состояние входа пользователя; браузер хранит соответствующую cookie.

Токен — временное значение, подтверждающее право выполнить сброс. Его нельзя публиковать, как и пароль. Ответ формы одинаков для известных и неизвестных адресов, чтобы не выдавать список зарегистрированных пользователей.

Реально исправлены две ошибки: письмо сначала содержало localhost, недоступный с телефона; затем вход по email не поддерживался. Теперь используется проверенный внешний адрес, а вход принимает email или логин. Пользователь подтвердил и открытие формы, и успешный вход с телефона после смены пароля.

127.0.0.1 / localhost означает «это же устройство». На телефоне такой адрес указывает на телефон. Cloudflare Tunnel даёт временный HTTPS-доступ к приложению на компьютере. Он не переносит сервер в облако: компьютер и службы должны работать. При смене временного адреса старые письма не обновляются — нужно запросить новое.

Подтверждение email при регистрации и запрет входа до подтверждения не включены по отдельному решению владельца.

## 8. Какие проверки выполнены

Числа разных этапов нельзя складывать: это повторные запуски пересекающихся наборов.

| Проверка | Зафиксированный результат |
|---|---|
| Последний найденный полный прогон до последних изменений входа | 336 Django-тестов, успешно; .local/test-smtp-retry-full.log |
| После исправления внешних ссылок восстановления | 35 тестов восстановления и почты, успешно |
| После добавления входа по email | 10 целевых тестов входа, регистрации и восстановления, успешно |
| Последние проверки языков | 5940 утверждений по переводу, 747 по границам авторского содержимого |
| Последние build и lint | Успешно |
| Резервные копии | Реальное восстановление в отдельные базы и сверка вложений |
| Живая проверка | HTTPS-страница/API отвечают, новая форма видна; пользователь вошёл с телефона |

После последнего исправления полного прогона всех тестов заново не было: выполнен целевой набор и проверки интерфейса. Это важно честно отличать.

Серверные тесты проверяют разрешённые и запрещённые действия: доступ к чужой группе, попытки обойти роли, сроки, лимиты попыток, хранение ответов, оценки, загрузки и удаление файлов, поведение при ошибках. Тесты восстановления проверяют одноразовость/истечение ссылки, слабые пароли, старые сессии, ошибки доставки и выбор получателя. Новые тесты входа проверяют email, логин, регистр, пробелы, отключённые аккаунты, неоднозначность и CSRF.

CSRF — защита от выполнения действий в вашей сессии со стороннего сайта. Для запросов изменения используется специальный токен. Она не заменяет пароль и проверку роли.

Build — создание готовой сборки; успешная сборка не доказывает правильность всех учебных сценариев. Lint — автоматический анализ правил и возможных ошибок кода. Автотест проверяет заранее описанный сценарий. Регрессионный тест не даёт исправленной ошибке незаметно вернуться. Ручная проверка показывает, что реальный пользователь смог пройти сценарий в браузере.

## 9. Что ещё не следует обещать

- Постоянное размещение, домен и эксплуатация 24/7 пока не настроены.
- Нет обещания подтверждённых почтовых адресов всех зарегистрированных пользователей.
- Не выполнена заявленная нагрузочная проверка на сотни/тысячи одновременно работающих людей.
- Нет заявления о независимом аудите безопасности или завершённом тестировании на проникновение.
- Нет автоматической внешней реплики резервных архивов.
- Аналитика не доказывает личность за устройством и причинное влияние урока.
- Система не заявляется полным аналогом Stepik; платежи, видеотрансляции и другие дополнительные подсистемы не следует приписывать проекту.

## 10. Как самостоятельно добавлять функции

Начинайте с поведения пользователя. Например: «Учитель задаёт дедлайн группе А; группа Б не меняется; после дедлайна читать можно; незавершённое прохождение помечается просроченным».

Затем определите: какие данные хранить, к чему они относятся, кто может их менять, что произойдёт при ошибке, как это проверить.

Рабочая последовательность:

1. Описать сценарий, права и граничные случаи обычными словами.
2. Найти нужную модель. Срок группы относится к запуску и модулю, а не ко всему Course.
3. Изменить модели и создать миграцию. Перед изменением рабочей базы сохранить копию.
4. Реализовать серверную проверку прав и значений. Нельзя доверять role, student_id или оценке из браузера.
5. Подключить API к форме и обработать загрузку, успех и ошибку.
6. Добавить системные тексты в RU/KK/EN, сохранив язык авторского содержания.
7. Проверить успешный сценарий и попытку обойти ограничение; тестировать в отдельной базе.
8. Собрать интерфейс, проверить нужные роли в браузере и на телефоне.
9. Применить миграции/обновление к работающей версии и убедиться, что проверяете именно новую сборку.
10. Записать изменение и ограничения в документацию.

Пример серверного мышления: недостаточно нарисовать кнопку «Сохранить дедлайн». Сервер должен отклонить запрос чужого преподавателя, дату раньше открытия и изменение не той группы. Внешний ключ и ограничения базы дополняют эту проверку.

## 11. Что изучать по порядку

1. Основы Python и JavaScript: функции, коллекции, исключения, асинхронность и модули.
2. HTML/CSS, формы, React: компоненты, props, state, обработчики и запросы к серверу.
3. HTTP, JSON, cookies и различие входа в аккаунт и прав доступа.
4. SQL/PostgreSQL: таблицы, внешние ключи, JOIN, индексы, ограничения и транзакции.
5. Django: модели, ORM, views, urls, migrations, validation и tests.
6. Права учебной системы: User → CourseRun → Enrollment → ответ/оценка.
7. S3, фоновая работа, резервирование и журналирование ошибок.
8. Развёртывание, Git, автоматические проверки и мониторинг.

Учебная самостоятельная задача: добавьте преподавателю поле «Примерное время урока в минутах». Сначала только модель, миграция и форма; затем проверка диапазона и прав; затем отображение студенту, переводы и тест. Работайте в отдельной учебной копии, не экспериментируйте на действующих результатах студентов.

После этого попробуйте расширение: индивидуальная дата дедлайна для одного Enrollment. Объясните, почему она не должна менять сроки всей группы, и напишите проверки для обоих студентов. Если можете провести функцию через модель → API → UI → права → тесты и объяснить каждое решение, вы понимаете архитектуру, а не просто повторяете команды.

## 12. Команды и инструкции проекта

Из корня LMS в PowerShell:

```powershell
.\Start-LMS.ps1
.\Start-LMS-Share.ps1
.\Stop-LMS-Share.ps1
```

Локальный старт и внешняя ссылка — разные действия. Актуальный временный адрес находится в .local/temporary-link.txt.

Из backend:

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
```

Автотесты должны использовать отдельную тестовую базу и локальное тестовое хранилище; настройки действующих S3/SMTP нельзя использовать для произвольных учебных экспериментов. Не запускайте команды восстановления поверх рабочей базы.
