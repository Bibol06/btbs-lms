# Два администратора BTBS

Работа разделена на две области. Имя сотрудника и его роль отображаются отдельно.

| Полномочия | Системный администратор | Администратор обучения | Владелец платформы |
|---|---|---|---|
| Состояние БД, место на диске, состояние S3 | Да | Нет | Да |
| Пользователи, создание и удаление студентов | Да | Нет | Да |
| История входов и устройств | Да | Нет | Да |
| Все курсы, группы, преподаватели | Нет автоматически | Да | Да |
| Модули, дедлайны, тесты, задания | Только при отдельном назначении в команду курса | Да | Да |
| Учебные результаты, проверки и аналитика | Нет автоматически | Да | Да |
| Назначение административных ролей | Нет | Нет | Да |

Системный кабинет LMS показывает состояние приложения. Он не предоставляет доступ к ОС, AWS Console, ключам S3 или Django admin. Развёртывание, резервные копии и обслуживание сервера выполняются отдельно через инфраструктурные инструменты.

## Что создано для проверки

- **Толеубаев Арман — Системный администратор**, логин `demo_system_admin`. Стартовая страница — «Система и хранилище».
- **Касымова Мадина — Администратор обучения**, логин `demo_learning_admin`. Стартовая страница — «Обзор обучения».
- **Жайлыбаев Бибол — Владелец платформы**. Прежние аккаунты `admin` и `demo_admin` сохраняют полный доступ и прежние пароли.

Имена новых администраторов демонстрационные, это не назначения реальных сотрудников. Для каждого создан отдельный случайный пароль, сохранённый только в локальном игнорируемом файле `.local/demo-access.json`: раздел `accounts`, записи `system_admin` и `learning_admin`. Пароли не публикуются в документации. После демонстрации владелец назначает роли реальным сотрудникам, а демонстрационные учётные записи следует отключить перед рабочим запуском.

## Как назначать сотрудников

Владелец открывает **Пользователи → Назначить область ответственности**, выбирает существующего пользователя, роль и нажимает **Сохранить полномочия**. В карточках выше видны назначенные ответственные. Саморегистрация создаёт студента. Две служебные роли не могут назначать административные права. Назначения сохраняются в системном журнале.

Ограничения проверяет сервер на каждом запросе. Подмена адреса страницы или ручной вызов API не даёт чужих полномочий. В одной области допустимо несколько ответственных: это две роли, а не жёсткое ограничение количества сотрудников.

## Повторная подготовка демо

Из каталога `backend`: `.venv\Scripts\python.exe manage.py setup_demo_admins`.

Команда работает только при `DEBUG=True`. Повторный запуск не меняет пароли и существующие аккаунты. При совпадении логина с чужой учётной записью команда отменяет изменения. Для рабочей базы роли назначаются владельцем существующим аккаунтам, а не этой демонстрационной командой.

Подход соответствует разделению полного администрирования и делегированного управления обучением: [Moodle — Manager](https://docs.moodle.org/403/en/Manager), [Site administrators](https://docs.moodle.org/405/en/Site_administrators). Матрица выше описывает конкретные полномочия BTBS.
